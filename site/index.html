The procedure

Each round is a challenge and a response, written to disk, until the reviewer approves, the round cap is reached, or you cancel.

  1. 1Coderimplements the task

    Claude does the work in your session and writes a summary of the round to round-01-coder.md.

  2. 2Reviewerchallenges by ID

    A separate CLI agent reads the diff and the summary, raises comments R1-C1, R1-C2 with a severity and whether each is blocking, and ends with a verdict.

  3. 3Coderanswers every ID

    Each comment is fixed, or declined with a reason. The next review grades every answer: resolved, unresolved, or declined and accepted or rejected.

  4. 4Repeatuntil approved

    The loop ends when the reviewer approves with no blocking comment, at the round cap, or when you cancel. /review-continue adds rounds to a loop that hit its cap.

Equipment

  1. 1Reviewera separate agent

    Codex or Claude as its own process, with its own model and reasoning effort. The coder never reviews its own work.

  2. 2Recordevery round on disk

    .review-loop/<id>/round-NN-coder.md and round-NN-review.md: each agent reads the other's file, and you can audit the whole exchange afterwards.

  3. 3Stop hookholds Claude to the task

    Installed as a plugin, a Stop hook keeps Claude on the loop until the reviewer approves or the round cap is reached.

  4. 4Presetsfocus each agent

    By default the reviewer works as code reviewer, QA engineer and security engineer; the coder as architect, tech-stack evaluator, security, backend and SecOps engineer.

  5. 5Dashboardevery loop on one page

    A self-contained page of your loops, their comments and verdicts, and --share for a read-only copy to send a teammate.
